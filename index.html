[01] THE BOTTLENECK

CRITICAL THREAT LANDSCAPE

SHARED KERNEL VULNERABILITIES

Standard container runtimes (runc) share the host Linux kernel. Adversarial AI evaluation suites frequently execute untrusted payload code that can exploit kernel surfaces:

  • Host OS syscall exposure (dirty_pipe, io_uring privilege escalation)
  • Container breakout allowing direct node takeover
  • Memory bus snooping and cache-timing attacks on multi-tenant GPUs

BENCHMARK DISTORTION

Direct exposure between Red Team attackers and model workers compromises scientific validity and defensive secrets:

  • KV-cache contamination between sequential attack turns
  • Defensive guardrail rule leakage to red-team adversaries
  • Unvetted models erroneously passing safety benchmarks due to prompt leakage

ARCHITECTURAL MANDATE & ZERO LEAKAGE

Design mandate for bulletproof adversarial safety testing and multi-tenant evaluation infrastructure:

  • Zero-knowledge blinded mediation between red adversary and blue evaluator
  • Enforced statelessness with atomic VRAM purging
  • Deterministic performance overhead — Design Target: <12 ms

[03] DOCKER COMPOSE NETWORK BRIDGE ISOLATION

SUBNET TOPOLOGY & IPTABLES

The multi-tier Docker Compose specification isolates untrusted Red runners from the protected inference engine and evaluation scorers via internal Linux network namespaces. Only the stateless Broker container joins both subnets.
